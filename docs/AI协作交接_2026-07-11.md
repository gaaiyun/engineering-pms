## 6. 当前已确认的问题分级

### P0：PocketBase 权限规则存在实际越权

在临时复制库启动 PB 后，REST 级别复现如下，均返回 200：

- 匿名用户可注册 `role=admin`。
- 员工可 PATCH 自己的 `role` 为 `admin`。
- 员工可创建项目。
- 员工可在任意项目创建任务。
- 员工可给经理伪造通知。
- 员工可列出 comments / progress_logs / flower_logs / handoffs / audit_logs 等多类数据。

相关规则来源：

- `users.createRule = ""`
- `users.updateRule = @request.auth.id = id || @request.auth.role = "admin"`
- `projects.createRule = @request.auth.id != ""`
- `tasks.createRule = @request.auth.id != ""`
- `notifications.createRule = @request.auth.id != ""`
- 多个历史 collection 仍使用宽泛 `@request.auth.id != ""`

处理优先级：最高。后续大幅优化前应先修权限，否则视觉和功能优化会建立在不安全的数据层上。

### P0/P1：AI Key 服务端化未真正闭环

文档声称 v3.04 起 API key 服务端代理、不暴露浏览器，但当前代码仍有：

- `frontend\src\pages\SettingsPage.tsx`：读取/写入 `localStorage.sf_api_key`。
- `frontend\src\pages\admin\AIConsole.tsx`：要求输入 SiliconFlow API Key 并写 localStorage。
- `frontend\src\pages\ManagerDashboard.tsx`：从 localStorage 读取 API Key。
- `frontend\src\lib\ai-service.ts`：PB proxy 失败后会用 browser direct fallback 调 SiliconFlow。
- `backend\pb_hooks\llm_proxy.pb.js`：只要求登录，未限制 admin/manager，也没有配额/审计。

处理建议：删除浏览器直连 fallback；前端不再保存 Key；代理端限制 admin/manager 或按业务明确授权，并增加最小日志、错误脱敏和调用审计。

### P1：线上部署链路疑似断裂

- 静态 Web 可访问。
- PB 端口健康检查外部超时。
- `/pb/api/health` 不是真 PB health，而是前端 HTML。
- APK 和线上 JS 都依赖 PB 可达，否则登录、数据、实时通知不可用。

处理建议：复核宝塔/Nginx 反代、PB 进程、端口安全组、防火墙、前端 `VITE_PB_URL`。

### P1：APK 发布状态不符合“production_ready”名称

- 当前 APK 为 debug 签名。
- targetSdk 为 33；Android 14/15 前台服务约束虽有代码兜底，但发布验收还不足。

处理建议：配置 release keystore、构建 release APK、重新签名验签、设备实测登录和后台通知。

### P2：Web 视觉和交互

- 通知页 `SwipeAction` 在桌面/移动均造成横向溢出。
- 设置页版本号仍是 `v2.1.0`。
- React 19 + antd-mobile 5 有兼容 warning。
- 通知列表被历史/E2E 消息污染，视觉密度高。
- `npm run lint` 失败，工程质量门禁不可用。

处理建议：桌面通知改显式操作按钮，移动保留滑动；统一版本来源；决定 React 18 降级或 antd-mobile React 19 兼容方案；整理测试数据或增加筛选/归档。
