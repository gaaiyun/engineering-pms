# EngineeringPMS 宝塔部署与生产运维手册

> 更新日期：2026-07-12
> 线上 PocketBase：0.22.21
> 本手册以当前服务器真实状态为准。旧的 `nohup`、`pkill`、在线覆盖 `data.db`、整目录上传 migrations/hooks 流程全部废止。

## 1. 线上结构

```text
浏览器 ──HTTP 80──> Nginx / 宝塔站点
                       └── /www/wwwroot/project_v2

Web / Android App ──HTTP 8090──> PocketBase 0.22.21
                                  ├── systemd: pocketbase.service
                                  ├── /www/server/pocketbase/pocketbase
                                  ├── /www/server/pocketbase/pb_data
                                  ├── /www/server/pocketbase/pb_migrations
                                  └── /www/server/pocketbase/pb_hooks
```

当前 Web/App 默认直连 `http://8.134.9.77:8090`。`/pb` HTTPS 反代属于后续安全收口，不是当前已上线事实。

## 2. 宝塔面板分别负责什么

- “网站”：管理 Nginx 站点、域名、SSL、静态 Web 根目录。
- “文件”：查看 Web、PocketBase、备份和部署 staging 文件。
- “终端”：执行 systemd、健康检查、迁移与校验命令。
- “安全/防火墙”：在 Web/App 都切到 HTTPS `/pb` 后关闭公网 8090。
- “计划任务”：可配置备份检查，但不要再配置第二个 PocketBase 进程守护。

Android APK 不需要上传到宝塔。APK 在 Windows 构建，连接宝塔服务器上的 PocketBase API。

## 3. PocketBase 日常管理

PocketBase 已由 systemd 和专用 `pocketbase:pocketbase` 账户运行。禁止再用 `nohup` 或宝塔进程守护。

```bash
systemctl status pocketbase --no-pager -l
systemctl is-enabled pocketbase
systemctl is-active pocketbase
ps -o user,group,pid,etimes,cmd -C pocketbase
ss -lntp | grep ':8090'
curl -i --max-time 5 http://127.0.0.1:8090/api/health
journalctl -u pocketbase --since '30 minutes ago' --no-pager
```

安全重启：

```bash
systemctl restart pocketbase
sleep 3
systemctl is-active pocketbase
curl -fsS --max-time 5 http://127.0.0.1:8090/api/health
```

只在明确维护窗口停止：

```bash
systemctl stop pocketbase
ss -lntp | grep ':8090' || true
```

## 4. 如何使用数据库

### 4.1 正常业务使用

- Web/App 使用 PocketBase REST API 和 Realtime SSE；不要直接写 SQLite。
- 管理集合、查看记录和设置服务端密钥使用 PocketBase Admin UI：`http://8.134.9.77:8090/_/`。
- 代码中的统一客户端是 `frontend/src/lib/pocketbase.ts`，业务数据 Hooks 在 `frontend/src/lib/api.ts`。
- 生产结构变更只能通过经过副本演练的单个 migration 上线。

### 4.2 只读排障

```bash
cd /www/server/pocketbase || exit 1
sqlite3 -readonly pb_data/data.db 'PRAGMA quick_check;'
sqlite3 -readonly pb_data/data.db \
  'SELECT name FROM _collections ORDER BY name;'
sqlite3 -readonly pb_data/data.db \
  'SELECT file,applied FROM _migrations ORDER BY applied DESC LIMIT 30;'
```

禁止：

- PocketBase 运行中用 SQLite 修改业务表；
- 把本地 `backend/pb_data/data.db` 覆盖生产库；
- 单独复制运行中的 `data.db` 而忽略 WAL/SHM；
- 执行 `database_rebuild.mjs` 连接生产库；
- 输出 `app_settings.value`、token 或密码到聊天和日志。

## 5. 备份与恢复

当前 PocketBase 内置设置已核验为：周一/周三 00:00、最多 10 份；日志保留 5 天。历史备份曾因服务掉线而中断，所以不能只看配置，必须看最新文件时间。

```bash
ls -lah /www/server/pocketbase/pb_data/backups
find /www/server/pocketbase/pb_data/backups -maxdepth 1 -type f \
  -printf '%TY-%Tm-%Td %TH:%TM %s %f\n' | sort
```

每次发布前创建冷备份：

```bash
cd /www/server/pocketbase || exit 1
test "$(df -Pk . | awk 'NR==2 {print $4}')" -gt 5242880 || {
  echo '可用空间不足 5GB，停止维护'; exit 1;
}

STAMP=$(date +%Y%m%d_%H%M%S)
BACKUP="/www/server/pocketbase/maintenance_backups/$STAMP"
systemctl stop pocketbase
while ss -lntp | grep -q ':8090'; do sleep 1; done
mkdir -p "$BACKUP"
cp -a pb_data "$BACKUP/pb_data"
sqlite3 -readonly "$BACKUP/pb_data/data.db" 'PRAGMA quick_check;'
systemctl start pocketbase
curl -fsS --retry 10 --retry-delay 1 --retry-connrefused \
  http://127.0.0.1:8090/api/health
echo "Backup: $BACKUP"
```

只有 `quick_check` 输出 `ok` 才算有效。恢复属于高风险操作：必须停服务、保留故障现场、从已验证冷备恢复整个 `pb_data`，恢复权限为 `pocketbase:pocketbase`，再做 health/login/CRUD 验收。

## 6. 发布 Web

### 6.1 本地构建

```powershell
Set-Location 'G:\项目管理软件_v2\frontend'
$env:VITE_PB_URL = 'http://8.134.9.77:8090'
npm run build
if ($LASTEXITCODE -ne 0) { throw 'Web build failed' }
```

确认 `frontend/dist/index.html` 使用根路径 `/assets/...`，并确认 JS 内含正确 PB URL、不含 localhost。

### 6.2 staging 与原子切换

不要在宝塔里先删除线上文件，也不要对站点根目录执行裸 `rsync --delete`。

```powershell
$stamp = Get-Date -Format 'yyyyMMdd_HHmmss'
tar -C 'G:\项目管理软件_v2\frontend\dist' -czf "G:\dev-cache\releases\engineering-pms-web-$stamp.tgz" .
scp "G:\dev-cache\releases\engineering-pms-web-$stamp.tgz" root@8.134.9.77:/www/server/panel/tmp/
```

服务器：

```bash
set -euo pipefail
STAMP=$(date +%Y%m%d_%H%M%S)
ROOT=/www/wwwroot/project_v2
STAGE=/www/wwwroot/.project_v2_stage_$STAMP
BACKUP=/www/wwwroot/.project_v2_backup_$STAMP
ARCHIVE=$(ls -1t /www/server/panel/tmp/engineering-pms-web-*.tgz | head -1)

mkdir -p "$STAGE"
tar -xzf "$ARCHIVE" -C "$STAGE"
test -f "$STAGE/index.html"
test -d "$STAGE/assets"
cp -a "$ROOT" "$BACKUP"
[ -f "$ROOT/.user.ini" ] && cp -a "$ROOT/.user.ini" "$STAGE/.user.ini"

mv "$ROOT" "${ROOT}.old_$STAMP"
mv "$STAGE" "$ROOT"
nginx -t
systemctl reload nginx
curl -fsS --max-time 10 http://127.0.0.1/ >/dev/null
echo "Web backup: $BACKUP"
```

若 `nginx -t` 或页面检查失败，立即把旧目录移回。发布后验证 `/`、`/login`、`/app`、`/system/users` 深链接刷新，检查浏览器控制台与 Network。

## 7. 发布 migration 与 hooks

生产与本地迁移历史已经分叉。永远不要上传整个 `backend/pb_migrations`，不要运行 `history-sync`。

正确流程：

1. 导出线上 `_collections`、`_migrations` 与规则；
2. 下载生产 `data.db` 到 G 盘隔离目录；
3. 只放本次 migration，在同版本 PocketBase 0.22.21 副本运行 `migrate up`；
4. 跑权限正反例、业务 CRUD、通知/AI Hook 测试和 `quick_check`；
5. 线上冷备；
6. 逐个上传审核过的 migration/hook；
7. `chown root:root` 代码文件，目录对服务账户只读；
8. `systemctl restart pocketbase`；
9. 检查 journal、health、登录和真实数据流。

示例（文件名必须替换成本次审核通过的明确清单）：

```bash
install -o root -g root -m 0644 /tmp/NEW_MIGRATION.js \
  /www/server/pocketbase/pb_migrations/NEW_MIGRATION.js
install -d -o root -g root -m 0755 /www/server/pocketbase/pb_hooks
install -o root -g root -m 0644 /tmp/SAFE_HOOK.pb.js \
  /www/server/pocketbase/pb_hooks/SAFE_HOOK.pb.js

cd /www/server/pocketbase
systemctl stop pocketbase
./pocketbase migrate up
systemctl start pocketbase
curl -fsS --retry 10 --retry-delay 1 --retry-connrefused \
  http://127.0.0.1:8090/api/health
journalctl -u pocketbase --since '10 minutes ago' --no-pager
```

仓库原有 `audit_logs_reject_sync.pb.js`、`handoffs_status_sync.pb.js`、`project_progress_sync.pb.js` 未完成生产安全复核前，不得原样上线。

## 8. Nginx 与 `/pb`（可选安全收口）

当前不强制反代。需要 HTTPS 时，先备份宝塔站点配置，再引用 `deploy/pocketbase/nginx-pb.conf`。该模板包含 SSE 所需的 HTTP/1.1、关闭缓冲和长超时。

```bash
cp -a /www/server/panel/vhost/nginx/8.134.9.77.conf \
  /www/server/panel/vhost/nginx/8.134.9.77.conf.bak.$(date +%Y%m%d_%H%M%S)
nginx -t
systemctl reload nginx
curl -i --max-time 5 http://127.0.0.1/pb/api/health
```

只有新版 Web 和最终 APK 都通过 `/pb` 完成登录、CRUD、文件和 SSE 验收后，才把 systemd 改为 `127.0.0.1:8090` 并关闭公网 8090。任一失败都保留当前公网链路并回滚 Nginx。

## 9. APK 与宝塔的关系

- 宝塔上不构建 APK，也不需要把 APK 放进 `/www/wwwroot/project_v2`。
- APK 的 `PocketBaseUrl` 必须指向手机能够访问的公网 API。
- 当前用 `http://8.134.9.77:8090`；未来切 HTTPS `/pb` 后必须重新构建。
- 详细构建、签名和真机验收见 `docs/android-apk.md`。

## 10. 故障速查

PocketBase 打不开：

```bash
systemctl status pocketbase --no-pager -l
journalctl -u pocketbase -n 120 --no-pager
ss -lntp | grep ':8090'
curl -i --max-time 5 http://127.0.0.1:8090/api/health
```

Web 打开但登录失败：检查当前入口 JS 中的 PB URL、8090 公网连通性、浏览器 Network/CORS；不要先重装 PocketBase。

深链接白屏：确认 Nginx 有 `try_files $uri $uri/ /index.html;`，同时 `index.html` 使用 `/assets/...` 根路径而不是 `./assets/...`。

`database disk image is malformed`：先确认是 `logs.db` 还是 `data.db`。业务库 `data.db` 非 `ok` 时立即停止一切迁移和部署，保留现场并从验证备份恢复；不要删除业务库。
